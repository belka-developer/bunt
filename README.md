# Бунт

Единый центр сетевых инструментов для Windows. Первым внутри будет запрет для Discord и YouTube на основе [zapret-discord-youtube](https://github.com/Flowseal/zapret-discord-youtube), Telegram на основе [tg-ws-proxy](https://github.com/Flowseal/tg-ws-proxy), VPN-клиент FPTN с защитой сети, профили WireGuard и AmneziaWG, DNS и VLESS на ядре Xray-core.

Приложение написано на Tauri 2 (Rust и обычные HTML, CSS, JS) и обновляется само из GitHub Releases, когда пользователь нажимает кнопку.

> **Статус: прототип.**
> Настоящее: окно, значок в трее, один экземпляр, проверка и установка обновлений самого Бунта.
> Макет с примерными данными: запрет Discord и YouTube, версии компонентов (помечены «демо»), проверка целостности, настройки. Настройки пока не сохраняются между запусками.
> Запрет для Discord/YouTube и для Telegram по умолчанию не установлен: пользователь сам нажимает «Установить» на главной или в разделе. Для Discord/YouTube установка настоящая: Бунт берёт последний релиз `Flowseal/zapret-discord-youtube`, проверяет хеш, распаковывает в `modules\discord\<версия>\` рядом с exe. Для Telegram Бунт берёт исходники последнего релиза `Flowseal/tg-ws-proxy` в `modules\telegram\<версия>\`, ставит рядом встроенный Python (`runtime`) и запускает прокси без окна; настройки и лог лежат в `modules\telegram\data`.

## Запуск для разработки

Нужны Windows 10 или 11, [Rust](https://rustup.rs) (stable), Node.js 20+ и WebView2 (в Windows 11 он уже есть).

```
npm install
npm run dev
```

Интерфейс лежит в `ui/` и ничем не собирается. Правки в `index.html`, `styles.css` и `app.js` видны после перезапуска окна. Файл `ui/index.html` можно открыть и в обычном браузере: так виден макет без Rust. Если добавить к адресу `?app`, окно выглядит как в приложении.

## Обновления из GitHub

### Как это работает

1. Пользователь нажимает «Проверить» на главной или «Проверить обновления» в меню трея. При запуске приложение тоже тихо проверяет обновления, и об этом сообщает, только если версия новее.
2. Приложение скачивает небольшой файл `latest.json` по адресу `https://github.com/belka-developer/bunt/releases/latest/download/latest.json`.
3. Если там версия новее установленной, в сводке появляется кнопка «Обновить». Ничего не скачивается, пока её не нажали.
4. По нажатию приложение скачивает установщик, проверяет его подпись по публичному ключу, зашитому в приложение, запускает установщик и перезапускается. Если подпись не совпала, ничего не ставится.

Установщик ставит Бунт для всех пользователей в Program Files, поэтому при обновлении Windows показывает запрос UAC.

### Настройка (один раз)

1. Создайте пару ключей для подписи обновлений. Команда спросит пароль:

   ```
   npx tauri signer generate -w "$HOME/.tauri/bunt.key"
   ```

   В PowerShell путь пишется так: `$HOME\.tauri\bunt.key`. Рядом появится файл `bunt.key.pub`.

2. Вставьте содержимое `bunt.key.pub` в `src-tauri/tauri.conf.json`, поле `plugins.updater.pubkey` (вместо `REPLACE_WITH_PUBLIC_KEY`).

3. В репозитории на GitHub откройте Settings, Secrets and variables, Actions и добавьте два секрета:
   - `TAURI_SIGNING_PRIVATE_KEY`: содержимое файла `bunt.key`;
   - `TAURI_SIGNING_PRIVATE_KEY_PASSWORD`: пароль от ключа.

> Приватный ключ нельзя коммитить, и его нельзя терять. Без него вы не сможете подписать новую версию, и всем пользователям придётся переустанавливать Бунт вручную.

Репозиторий и релизы должны быть публичными, иначе приложение не скачает `latest.json`.

### Быстро получить exe без ключей

Откройте на GitHub вкладку Actions, выберите слева «Сборка для проверки» и нажмите Run workflow. Минут через десять внизу страницы запуска, в разделе Artifacts, появится `Bunt-setup` с установщиком. Ключи для этого не нужны, но обновляться такая сборка не сможет: она без подписи.

### Выпуск новой версии

```
npm run bump -- 0.1.1
git commit -am "v0.1.1"
git tag v0.1.1
git push && git push --tags
```

`bump` меняет версию сразу в `tauri.conf.json`, `Cargo.toml` и `package.json`. Тег запускает workflow `.github/workflows/release.yml`: он собирает установщик, подписывает его и публикует релиз вместе с `latest.json`. Если версия в `tauri.conf.json` не совпадает с тегом, сборка остановится.

Текст релиза на GitHub показывается пользователю как описание обновления, поэтому пишите его по-человечески.

### Как проверить всю цепочку

1. Выпустите `v0.1.0` и установите Бунт из релиза.
2. Выпустите `v0.1.1`.
3. В запущенном 0.1.0 нажмите «Проверить», затем «Обновить».

Локальная сборка установщика (`npm run build`) требует переменной окружения `TAURI_SIGNING_PRIVATE_KEY` (путь к ключу или его содержимое), потому что включены файлы для обновлений. Для разработки хватает `npm run dev`.

Установщик пока не подписан сертификатом кода, поэтому Windows SmartScreen может показать предупреждение.

## Компоненты и права администратора

Всё скачанное лежит в папке `modules` рядом с `Bunt.exe` (обычно `C:\Program Files\Bunt\modules\`): `modules\<компонент>\<версия>\`, активная версия записана в `modules\state.json`, временные файлы в `modules\.staging\`. Новая версия ставится рядом со старой.

Запись в Program Files, запуск `winws` и драйвер WinDivert требуют прав администратора. Бунт стартует без них (иначе Windows не пускает его в автозапуск), а если прав нет, показывает кнопку «Дать права»: она перезапускает Бунт от имени администратора. Автозапуск это запись в разделе Run реестра, она видна в «Автозагрузке» диспетчера задач. Для `npm run dev` с запретом откройте терминал от имени администратора.

## Структура

```
src-tauri/   приложение на Rust: окно, трей, обновления
ui/          интерфейс: index.html, styles.css, app.js, fonts/
scripts/     bump.mjs: подъём версии
.github/     workflow выпуска релиза
```

## FPTN

Бунт скачивает официальный установщик из релиза `fptn-project/fptn`, тихо ставит его в `modules\fptn\<версия>` и запускает `fptn-client-cli.exe` без окна. Настройки, токен и состояние сессии лежат в `modules\fptn\data`. Перед подключением запоминается шлюз физического адаптера и статические DNS; после отключения или сбоя Бунт удаляет маршруты FPTN (через его адрес в туннеле и маршруты с метрикой 2 через шлюз), возвращает DNS и при желании удаляет адаптер Wintun. Нужны права администратора.

## WireGuard и AmneziaWG

Бунт скачивает MSI клиента из релиза `amnezia-vpn/amneziawg-windows-client` и не ставит его в систему: `msiexec /a` только распаковывает пакет в `modules\wg\<версия>`. Один клиент понимает и обычные конфиги WireGuard, и конфиги AmneziaWG (параметры Jc, S1, H1, I1 и другие). Профили `.conf` лежат в `modules\wg\data\profiles` и доступны только системе и администраторам. Профили со сценариями PostUp и PreDown не принимаются: они выполняются от имени системы.

Туннель работает как служба Windows: `amneziawg.exe /installtunnelservice` и `/uninstalltunnelservice`. Службе выставляется ручной запуск, поэтому после перезагрузки VPN сам не поднимется. Одновременно работает один туннель Бунта; чужие службы WireGuard и AmneziaWG не трогаются. По умолчанию `0.0.0.0/0` заменяется на `0.0.0.0/1` и `128.0.0.0/1`: клиент не включает брандмауэр-«выключатель», и Radmin VPN, Hamachi и локальная сеть продолжают работать. Перед подключением запоминаются шлюз и DNS физических адаптеров, после отключения или сбоя Бунт убирает следы туннеля без сброса сети Windows. Нужны права администратора.

## VLESS

Бунт ставит ядро [Xray-core](https://github.com/XTLS/Xray-core) в `modules\vless\<версия>\` (хеш архива проверяется, рядом кладётся подписанный wintun.dll) и запускает `xray.exe` скрыто. Профили: ссылки `vless://` (tcp, ws, grpc, httpupgrade, xhttp; none, tls, reality; Vision) и подписки по адресу (в том числе в base64), с обновлением списка. Ключи хранятся в `modules\vless\data` и доступны только администраторам, в интерфейсе их нет.

Два режима: **TUN** (виртуальный адаптер, идёт весь трафик, нужны права администратора) и **системный прокси** (локальные SOCKS и HTTP, в Windows включается системный прокси). Правила маршрутизации задаются по приложениям (имя процесса, путь или папка), доменам (`example.com`, `full:`, `regexp:`, `geosite:`) и сетям (`10.0.0.0/8`, `geoip:ru`): через VLESS, напрямую или блокировать; всё остальное идёт по варианту «по умолчанию». Локальная сеть по умолчанию идёт напрямую. Перед подключением запоминаются шлюз, DNS физических адаптеров и прежний системный прокси; после отключения или сбоя Бунт возвращает их без сброса сети Windows. Одновременно с FPTN и WireGuard VLESS не включается.

## DNS

Раздел меняет DNS-серверы активных физических адаптеров Windows: Cloudflare (1.1.1.1), Google (8.8.8.8), Quad9, AdGuard, Яндекс DNS, OpenDNS, Comss.one или свои адреса. Можно выбрать, на каких адаптерах менять, проверить скорость ответа серверов и по желанию включить шифрование DoH (Windows 11). Перед первой сменой Бунт запоминает прежние настройки: вернуть их можно кнопкой «Настройки до Бунта», либо вернуть автоматический DNS от роутера. Виртуальные адаптеры (VPN, Hyper-V) не трогаются. Пока включён FPTN или WireGuard, DNS не меняется: VPN управляет им сам. Состояние лежит в `modules\dns.json`. Нужны права администратора.
